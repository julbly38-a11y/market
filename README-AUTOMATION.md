## Правила роботи з власником (обов'язково)

- Ціни й націнку **не міняти без прямої вказівки**. Деплой лише за словом «деплой». Повернення коштів, остаточне видалення, переказ грошей, надсилання повідомлень постачальникам від імені власника: робить власник (або явний дозвіл у чаті). Не вводити за нього паролі/ключі.
- Деплой робити **з кореня репозиторію** (проєкт Vercel `forpost-shop`, домен forpost-shop.com): `env -u VERCEL_TOKEN -u VERCEL_TEAM_ID -u VERCEL_PROJECT_ID vercel --prod --yes`. З `shop/` піде в сторонній проєкт `shop`. Перший запуск інколи дає «Not authorized», повтор допомагає. Після деплою `git checkout shop/.gitignore`.
- Власник дратується від довгих пояснень і повторних питань: діяти, перевіряти самому («зайди і подивись»), коротко звітувати.
- Не комітити в репозиторій банківські реквізити (IBAN постачальників тощо): їх видно в кабінеті MyDrop у плашці при введенні передоплати.

## Поточна схема (що працює)

1. Каталог: `npm run sync` (`shop/scripts/sync-catalog.mjs`) тягне з MyDrop товари з `drop_price` (собівартість) і `price` (RRP). Асортимент обмежено файлом `shop/lib/assortment.mjs` (див. нижче). Після sync: `node --env-file=../.env scripts/classify.mjs`.
2. Ціна покупцю: `sellPrice(rrp, drop) = max(RRP, drop × (1+націнка))`, націнка під мінімум 10% чистого прибутку після податку (5% + 1% ВЗ) і комісії mono 1,3%. Товар без `drop_price` не продається. Файл `shop/lib/pricing.js`.
3. Замовлення `shop/app/api/order/route.js`: перевірка живої ціни/залишку/розміру/відділення НП, збереження в `market.orders`.
4. **Накладений платіж**: чернетка в MyDrop і **автоподача** `POST /dropshipper/api/orders/<id>/submit` для постачальників з `AUTO_SUBMIT_VENDORS` (за замовчуванням Oasis_Drop, Товарний Синдикат, Secret Shop, **BEZET**; BEZET додано в коміті `819a6a9`). Ліміт `COD_MAX_AMOUNT` 3000 ₴ і 3 замовлення на добу з номера. Перевірено наживо: замовлення 6651754 подане через API. `submitMydropOrder` (з `819a6a9`) повторює збої мережі, 429 і 5xx до 3 разів, перед повтором перевіряє, чи замовлення вже подане, при `description_required` повторює з приміткою; лист власнику показує код помилки подачі з підказкою (`submitErrorHint` у `lib/orders.js`).
5. **Картка (mono)**: вебхук `app/api/mono-webhook/route.js` після оплати створює чернетку й пробує подати з `prepay_from_balance` (`PREPAY_BALANCE_VENDORS`). Наживо дало `not_enough_balance` (баланс 0): замовлення лишається чернеткою, власнику йде лист.
6. ТТН і статуси: cron `/api/cron/order-sync` кожні 30 хв (pg_cron `order-sync`) читає з MyDrop `ttn`, статус, статус доставки, шле листи покупцю й власнику.
7. Моніторинг цін щодоби 05:30 UTC (`/api/cron/price-watch`), запити відгуків (`review-requests`).
8. Набори (`market.sets`) усі вимкнено (`active=false`).

## Що встановлено про MyDrop API (https://api.mydrop.com.ua, розділ «Версія для дропшиперів»)

Базовий URL `https://backend.mydrop.com.ua/dropshipper/api`, заголовок `X-API-KEY`. Cloudflare блокує Python urllib: використовувати curl або node fetch.

| Дія | Ендпоінт |
|---|---|
| Підключені постачальники (`id` зв'язки, не vendorId) | `GET /dropshipper_vendors` |
| Каталог з drop-цінами, залишками, варіаціями | `GET /export/dropshipper_vendors/<id>/products/json` (кеш ~15 хв) |
| Створити чернетку | `POST /orders` (товар: vendor_name/product_title/sku/price/amount/size_title або product_id/size_id) |
| **Перевірити без подачі** | `POST /orders/<id>/submit` з `{"dry_run":true,...}` |
| Подати постачальнику | `POST /orders/<id>/submit` (поля: prepay_amount, delivery_payment, full_prepay_amount, prepay_from_balance, generate_ttn, ttn, description, city, warehouse_number) |
| Скриншот оплати | `POST /orders/<id>/image` (multipart, поле `file`) |
| Читати замовлення (ttn, ttnTextStatus, deliveryStatus, orderStatus, submitted) | `GET /orders/<id>`, `GET /orders` |
| Змінити | `PUT /orders/<id>` (після подачі змінні лише облікові поля) |
| Вебхуки «Створення/Зміна замовлення» | налаштовуються в кабінеті, сторінка «API» (**ще не підключені**) |

Ключові висновки:
- **Дрібниці, що ламали подачу:** товар без розмірів має одну варіацію з назвою «-»; без `size_title` подача дає `product_size_required` (виправлено в `createMydropDraft`). Створення чернеток платне: потрібен тариф або безкоштовні замовлення (`subscription_required`).
- **Оплата в MyDrop.** Накладений платіж: постачальник сам збирає гроші з покупця й потім виплачує дропшиперу різницю (у Oasis написано: виплата лише після отримання накладеного платежу). Передоплата: або переказ на реквізити постачальника зі скриншотом (`payment_image_required`: Oasis, Secret Shop, BEZET), або з внутрішнього **балансу** MyDrop, який поповнює **лише постачальник** вручну (кнопки «Поповнити» немає). Баланс Oasis і Синдиката зараз 0. З балансу списується drop-ціна, не весь продаж. Реквізити постачальника видно в кабінеті у плашці «Важлива інформація» на сторінці редагування замовлення після натискання «Повна передплата» (Oasis: призначення платежу «оплата за товар»; Синдикат вимагає «вказати час оплати в примітці»).
- **Матриця dry_run** (перевірено 2026-10-27): накладений платіж проходить у всіх чотирьох (Oasis, Синдикат, Secret Shop, BEZET) без скриншота; передоплата з балансу проходить у Oasis/Синдикат/Secret Shop (dry_run баланс не перевіряє), у BEZET потрібен скриншот; переказ вимагає скриншот у Oasis/Secret Shop/BEZET.
- **ТТН.** Створює **постачальник** при обробці (у MyDrop напис «Очікуйте, коли постачальник створить ТТН»). Поля `generate_ttn` і `ttn` у `/submit` існують, але діють лише якщо постачальник дозволив у себе «Дозволити дропшиперам генерувати/вказувати свою ТТН» (інакше `external_ttn_not_allowed`; наживо dry_run це не виявляє). Куплений власником «Модуль для генерації ТТН» (8 €) вмикає форму для **власних відправок** дропшипера (контрагент Нової Пошти з ключем API, місто/відділення відправлення); для замовлень Oasis/Синдиката опції «Згенерувати ТТН» у формі **немає**. Постачальник також має опцію «Генерувати ТТН автоматично після додавання замовлення дропшипером»: у Oasis і Синдиката, схоже, вимкнена: замовлення подані о 02:16 і 02:44, о 12:24 ТТН досі немає.
- Допомога MyDrop прямо каже: за ТТН, наявність і виплати відповідає постачальник, не CRM.
- Якщо ТТН наша, накладений платіж отримуємо ми, а не постачальник; щоб гроші падали на рахунок ФОП автоматично, потрібна послуга НП «Контроль оплати» (договір з поштою, галочка в контрагенті).
